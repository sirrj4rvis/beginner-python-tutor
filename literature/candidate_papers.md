## A. Background: Generative AI in programming education

**1. Becker et al., "Programming Is Hard – Or at Least It Used to Be," SIGCSE 2023.**
DOI: 10.1145/3545945.3569759
A position paper on what AI code generators such as Codex and Copilot mean for teaching programming. It lists opportunities (examples, explanations, new exercises) and risks (copying, over-reliance, wrong code). Use it to motivate the problem: the tools are strong, but learning can suffer.

**2. Prather et al., "The Robots Are Here: Navigating the Generative AI Revolution in Computing Education," ITiCSE-WGR 2023.**
DOI: 10.1145/3623762.3633499
A large working-group report that combines a literature review with surveys and interviews of instructors and students about GenAI tools. It describes how teaching is changing and gives recommendations. Good as a broad background citation.

**3. Denny et al., "Computing Education in the Era of Generative AI," Communications of the ACM, 2024.**
DOI: 10.1145/3624720
A short magazine-style overview. It argues that GenAI shifts which skills matter, towards reading, testing and specifying code rather than only writing it. Useful in the Introduction.

**4. Finnie-Ansley et al., "The Robots Are Coming: Exploring the Implications of OpenAI Codex on Introductory Programming," ACE 2022.**
DOI: 10.1145/3511861.3511863
The authors gave real CS1 exam questions to Codex and found it scored better than most students. This shows a plain AI model simply hands out answers, which is the "copying" problem your system tries to avoid.

**5. Kazemitabaar et al., "Studying the Effect of AI Code Generators on Supporting Novice Learners in Introductory Programming," CHI 2023.**
DOI: 10.1145/3544548.3580919
A controlled study where young novices (ages 10–17) learned Python with and without Codex. The Codex group did better while practising, without a clear loss on later tasks done without AI, and learners with more prior knowledge benefited more. Shows AI help *can* support learning if used well.

## B. Generating exercises, explanations and examples

**6. Sarsa, Denny, Hellas, Leinonen, "Automatic Generation of Programming Exercises and Code Explanations Using LLMs," ICER 2022.**
DOI: 10.1145/3501385.3543957
Used Codex to create new programming exercises (with solutions and tests) and to explain code. Most exercises were sensible and new, but the tests and solutions were not always correct. Directly related to your Practice Generation mode.

**7. MacNeil et al., "Experiences from Using Code Explanations Generated by LLMs in a Web Software Development E-Book," SIGCSE 2023.**
DOI: 10.1145/3545945.3569785
Added GPT-3 explanations of different kinds (line-by-line, summary, concepts used) to an online textbook and measured how students used them. Students found them helpful. Related to your Concept Explanation mode.

**8. Leinonen et al., "Comparing Code Explanations Created by Students and Large Language Models," ITiCSE 2023.**
DOI: 10.1145/3587102.3588785
Compared explanations of the same code written by students and by GPT-3. Students rated the LLM explanations as easier to understand and more accurate on average. Supports using an LLM to explain concepts to beginners.

**9. Jury et al., "Evaluating LLM-generated Worked Examples in an Introductory Programming Course," ACE 2024.**
DOI: 10.1145/3636243.3636252
Built a tool that uses an LLM to create step-by-step worked examples and tried it in a real intro course. Students found the examples useful. Relevant to the small worked examples in your Concept Explanation mode.

## C. Error messages, feedback and hints

**10. Leinonen et al., "Using Large Language Models to Enhance Programming Error Messages," SIGCSE 2023.**
DOI: 10.1145/3545945.3569770
Gave Python error messages and the buggy code to Codex and asked for a plain-language explanation and a fix. The explanations were usually understandable, but the suggested fixes were less reliable. Very close to your Guided Feedback mode.

**11. Taylor et al., "dcc --help: Transforming the Role of the Compiler by Generating Context-Aware Error Explanations with LLMs," SIGCSE 2024.**
DOI: 10.1145/3626252.3630822
Added an LLM to the C compiler used in a large university course, so students get a simple explanation of compile and runtime errors, prompted not to give full solutions. Deployed at scale and mostly correct. Same idea as yours, but for C with a closed model.

**12. Phung et al., "Generating High-Precision Feedback for Programming Syntax Errors using LLMs," 2023.** *(preprint; also at EDM 2023)*
DOI: 10.48550/arXiv.2302.04662
Uses an LLM to fix Python syntax errors and explain them, then adds a checking step that throws away feedback it is not confident about. Shows the value of validating AI feedback before a student sees it.

**13. Kiesler, Lohr, Keuning, "Exploring the Potential of LLMs to Generate Formative Programming Feedback," FIE 2023.**
DOI: 10.1109/FIE58773.2023.10343457
Gave real student solutions to ChatGPT and classified the feedback it produced. The feedback was often helpful but sometimes misleading, and it sometimes included the full solution. Good evidence for your "solution leakage" metric.

**14. Pankiewicz & Baker, "Large Language Models (GPT) for Automating Feedback on Programming Assignments," 2023.** *(preprint)*
DOI: 10.48550/arXiv.2307.00150
Added GPT-3.5 feedback to an automatic grading platform used in a programming course. Students found it useful, but the authors raise concerns about students relying on it too much.

**15. Hellas et al., "Exploring the Responses of LLMs to Beginner Programmers' Help Requests," ICER 2023.**
DOI: 10.1145/3568813.3600139
Took real help requests from beginners and checked how Codex and GPT-3.5 answered them. GPT-3.5 found many of the issues but often included model-solution code even when told not to. A key citation for why prompting alone is not enough, which is your reason to fine-tune.

**16. Phung et al., "Automating Human Tutor-Style Programming Feedback: GPT-4 Tutor Model for Hint Generation and GPT-3.5 Student Model for Hint Validation," LAK 2024.**
DOI: 10.1145/3636555.3636846
GPT-4 writes hints for buggy Python programs, and a second model acting as a "student" tests whether each hint actually helps before it is shown. This improves hint quality. Related to your hint generation.

**17. Heickal & Lan, "Generating Feedback-Ladders for Logical Errors in Programming using LLMs," 2024.** *(preprint; also at EDM 2024)*
DOI: 10.48550/arXiv.2405.00302
Generates several levels of hints for the same bug, from vague to very specific, so a student only sees as much help as they need. Supports your step-by-step hint design.

**18. Al-Hossami et al., "Can Language Models Employ the Socratic Method? Experiments with Code Debugging," SIGCSE 2024.**
DOI: 10.1145/3626252.3630799
Created a hand-written dataset of buggy beginner programs paired with teacher-style Socratic dialogues, then tested whether LLMs can guide students with questions instead of answers. GPT-4 did best but was still behind humans. Very similar to your dataset idea (buggy code + teaching response).

## D. Deployed AI tutors with guardrails

**19. Liffiton, Sheese, Savelka, Denny, "CodeHelp: Using LLMs with Guardrails for Scalable Support in Programming Classes," Koli Calling 2023.**
DOI: 10.1145/3631802.3631830
An LLM assistant for programming classes that is designed not to show solution code. It was used in a real course, and students and instructors found it helpful. This is the system closest to yours. Main difference: it uses a closed API with prompt guardrails, while yours fine-tunes an open model.

**20. Sheese, Liffiton, Savelka, Denny, "Patterns of Student Help-Seeking When Using an LLM-Powered Programming Assistant," ACE 2024.**
DOI: 10.1145/3636243.3636249
Analysed the questions students sent to CodeHelp: debugging, implementation and concept questions. Useful for deciding which help types your tutor must support.

**21. Kazemitabaar et al., "CodeAid: Evaluating a Classroom Deployment of an LLM-based Programming Assistant that Balances Student and Educator Needs," CHI 2024.**
DOI: 10.1145/3613904.3642773
A semester-long deployment of an assistant in a large class. It avoids giving direct code and uses pseudo-code and annotated explanations instead. Gives lessons on balancing helpfulness against giving away answers.

**22. Liu et al., "Teaching CS50 with AI: Leveraging Generative AI in Computer Science Education," SIGCSE 2024.**
DOI: 10.1145/3626252.3630938
Harvard's CS50 built an AI "duck" tutor on top of a GPT-4 model, with guardrails so it guides students instead of solving their work. Used at large scale on campus and online. A well-known real-world example.

**23. Lyu et al., "Evaluating the Effectiveness of LLMs in Introductory CS Education: A Semester-Long Field Study," L@S 2024.**
DOI: 10.1145/3657604.3662036
Compared students who used an LLM tutor (CodeTutor) for a semester with students who did not. The tutor group improved scores, but students' opinion of the tool changed over time. Supports your pre-test/post-test evaluation design.

## E. Open-source and fine-tuned models for teaching

**24. Koutcheme et al., "Open Source Language Models Can Provide Feedback: Evaluating LLMs' Ability to Help Students Using GPT-4-As-A-Judge," ITiCSE 2024.**
DOI: 10.1145/3649217.3653612
Tested open-source LLMs on giving feedback for student programs, using GPT-4 to grade the feedback. Some open models came close to proprietary ones. Justifies your choice of a small open model.

**25. Hicke et al., "AI-TA: Towards an Intelligent Question-Answer Teaching Assistant using Open-Source LLMs," 2023.** *(preprint)*
DOI: 10.48550/arXiv.2311.02775
Built a course Q&A assistant on an open LLM (LLaMA-2) by combining retrieval (RAG) with fine-tuning on course data. The combination improved answer quality. Very close to your architecture (RAG + fine-tuned open model).
